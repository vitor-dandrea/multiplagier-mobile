Diagrama de camadas

Vitor · Camadas

O que cada camada faz

features/

Telas e controllers: auth, catálogo, carrinho, pagamento, conta e pedidos. Observam estado e disparam ações do usuário.

data/

Repositórios e modelos; SQLite (schema v5), seed do catálogo e regras de isolamento por usuário.

core/

Paleta dark+lime, validação de endereço e hashing de senha — utilitários sem UI.

Vitor · Design pattern

Repository + Observer

UI → Controller → Repository → SQLite
  • Repository — concentra acesso a dados; a UI não conhece SQL.
  • Observer (ChangeNotifier) — controller notifica widgets quando o estado muda.
  • Fluxo típico: toque na tela → método no controller → repositório → banco → notifyListeners().

Mauro · Segurança

Controles implementados

  • PBKDF2 — senha nunca em texto puro; salt + iterações via crypto.
  • Sessão id-only — shared_preferences guarda só o user id, não a senha.
  • SEC-001 — pedido de outro usuário = “não encontrado”.
  • SEC-003 — 5 logins falhos → bloqueio de 30 s.
  • Checkout — sem PAN/CVV; endereço completo snapshotado no pedido.
